# 第 2 章 規則與演練候選（page_0009～page_0012）

## (a) 規則候選

### R2-1 引用網路資料前先確認「是哪一個同名產品」

- 規則一句話：查到關於某工具的評測、教學或指令時，先確認它指的是哪一個產品／版本（開源 vs. 託管、哪個 repo），對不上就不引用。
- Why：本章指出有兩個「Paperclip AI」，許多報導把託管產品的問題（幻覺數字、版面壞掉）算到開源專案頭上；搞混的人等於在評判錯誤的工具（page_0009～page_0010）。
- How to apply：Claude 做研究或查文件時，每條引用都附上來源網址並核對 repo／網域（例如是否為 github.com/paperclipai）；出現「sign up」「subscription」「provider's server」等字眼時主動標記「可能是託管產品」。

### R2-2 開源免費 ≠ 運作免費：先估代理成本

- 規則一句話：導入任何「免費開源」的代理協調工具前，先估算接上的模型／代理實際會花多少錢。
- Why：本章迷思檢查明說：軟體免費，但連接的代理會產生真實成本（page_0010，並指向第 7 章）。
- How to apply：Claude 建議或安裝這類工具時，同時說明扣費來源（Max 訂閱的 claude -p 或 API Credits），預設走不扣 API 的路線，並提醒設定預算上限。

### R2-3 用「真實公司會不會有」判斷功能歸屬

- 規則一句話：設計多代理系統時，協調層只放「公司會有的東西」（組織圖、預算、核准、紀錄），實際產出交給代理。
- Why：作者要讀者把「代理＝員工、Paperclip＝公司」當公式：薪資、組織圖、核准屬於公司；親自寫文字是員工的事（page_0011）。
- How to apply：Claude 規劃主管代理／工廠架構時，檢查主控層是否混入了實作工作；混入就拆給子代理。

## (b) 演練候選

### D2-1 兩個「Paperclip AI」辨識練習（不需帳號）

- 步驟：
  1. 搜尋「Paperclip AI review」取 5 篇文章或影片。
  2. 依本章記憶法逐篇打勾：是否提到 github.com/paperclipai、MIT、自行下載啟動 → 開源；是否提到 sign up、subscription、雲端登入、付費 → 託管。
  3. 把結果整理成表格存到 `practice/ch02/two-paperclips.md`。
- 預期結果：至少能把每篇歸類為「開源」「託管」或「無法判斷」，並發現部分文章混用。

### D2-2 工具選型練習：工作流程建構器 vs. 代理協調層

- 步驟：列出 3 個你自己的自動化需求（例：收到信就記帳、每週自動寫週報、多代理寫一本書），依本章標準判斷「單一固定流程」或「多代理開放目標＋要管成本與責任」。
- 預期結果：得到一張需求對工具類型的對照表，理解多數單一流程用工作流程工具（如 n8n）更便宜穩定。
