# ch01｜從 AI 助理到 AI 公司

## 這章在講什麼

- 從「等指令的單一 AI 助理」跳到「被協調的 AI 勞動力」：一群代理有人盯大目標、有人分工、有人回報，你不必逐件啟動。
- Paperclip 不是新的 AI，而是控制層：智慧來自代理，秩序（角色、呈報線、預算、規則）來自 Paperclip。
- 之所以「現在可能」，是因為單一代理已能獨力完成整段工作；之所以「必要」，是因為多個代理沒有秩序就會重工、互相矛盾、陷入迴圈。
- 你的角色從執行者升級成所有者與監督者：少了動手，多了設定目標、劃邊界、審結果。
- 全書主軸：協調負責組織工作，不保證品質；「自主完成」不等於「結果正確」。

## 作者做過的實驗／例子

- 「AI 公司的一天」：清晨 CEO 代理在第一次心跳醒來，發現本週還缺一篇文章，委派研究員；下一次心跳寫手把資料寫成草稿，標「等待核准」；八點你讀過、改兩處、核准。
- 二十個會自我組織的助理 vs. 一個等你下令的助理：差別不在聰明，而在有沒有人領導。
- 工具與員工的對比：鐵鎚會等待，員工在框架內主動行動；Paperclip 的設計讀起來像人資手冊，因為它把代理當員工領導。

## 演練

> 說明：練習 1 完全不呼叫模型；練習 2 跑一次真心跳（researcher＋writer 各 1 次，共 2 次 `claude -p`）。整章合計 2 次。

### 練習 1：把自己的日常工作拆成一家「AI 公司」草稿

**目的**：體會 Paperclip 管的是「結構」——目標、角色、呈報線、預算——而不是工作內容本身。
**送給練習視窗的提示詞**：

```text
請讀 CLAUDE.md 與 paperclip_lite.py 的 SAMPLE_COMPANY，了解 company.json 的欄位（name、goal、agents[id/role/reports_to/model/max_calls/max_usd]、projects）。本練習不呼叫任何模型。
1. ch01/inventory.md：假設使用者是一位在求職、同時自學 ROS 2 的工程師。列出他一週會做的 8 件重複工作（例：看職缺、寫自介、整理學習筆記、回信…），每件標「適合交給代理／必須自己做／交給代理但要我核准」，並寫一句理由。
2. 依 inventory 寫 ch01/company-draft.json：1 個公司目標（可檢查的一句話）、1 個 ceo＋2～3 個部門主管或執行代理，每個代理寫清楚 role、reports_to、model（一律 haiku）、max_calls（2～5）、max_usd（≤0.30）；再寫 2 個 projects。不要把「必須自己做」的工作分給代理。
3. 檢查結構能被工具讀懂：
   PYTHONUTF8=1 python paperclip_lite.py init ch01/co > ch01/init.txt 2>&1
   把 ch01/company-draft.json 複製覆蓋 ch01/co/company.json
   PYTHONUTF8=1 python paperclip_lite.py org ch01/co > ch01/org.txt 2>&1
   （只跑 org；不要對這家公司跑 heartbeat，因為 ledger 還是範例代理的名字。）
4. ch01/role-shift.md：用 5 行以內說明，這家公司跑起來後使用者每天「少做什麼、多做什麼」，以及哪兩個點一定要他親自核准。
```

**觀察重點**：

- org.txt 是否真的畫出樹狀呈報線（不是只有平面清單）？
- 「必須自己做」的工作是否真的沒被分給代理？核准點是否落在對外或不可逆的動作上？
- 預算上限是否每個代理都有、而且偏緊？

### 練習 2：跑一次「AI 公司的一天」，你當審稿的所有者

**目的**：親眼看到「目標 → 委派 → 草稿 → 等待核准 → 人類決定」這條鏈，並體會「做完了」不等於「做對了」。
**送給練習視窗的提示詞**：

```text
本練習最多 2 次 claude -p 呼叫（只跑一次非乾跑 heartbeat）。所有輸出存到 ch01/。
1. PYTHONUTF8=1 python paperclip_lite.py init ch01/day > ch01/day-init.txt 2>&1
2. 先乾跑看代理會收到什麼：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch01/day --dry-run > ch01/day-dryrun.txt 2>&1
3. 真跑一次心跳：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch01/day > ch01/day-heartbeat.txt 2>&1
   （同一次心跳裡 researcher 先做 T001，writer 接著做 T002；若出現錯誤就停下，不要重試，把錯誤存檔回報。）
4. PYTHONUTF8=1 python paperclip_lite.py status ch01/day > ch01/day-status.txt 2>&1
5. 讀 ch01/day/outputs/T002.md。扮演所有者：把短文複製成 ch01/T002-reviewed.md，實際改兩處（一處用字、一處內容），每處在檔尾用一行說明為什麼改。
6. PYTHONUTF8=1 python paperclip_lite.py approve ch01/day T002 > ch01/day-approve.txt 2>&1
7. ch01/day-notes.md：(a) 對照書中「AI 公司的一天」，把每一步對到你剛剛看到的哪一行輸出；(b) 列出 T002 裡任何無法從 T001 輸出證實的說法（沒有就寫沒有）；(c) 為什麼 ceo 這次心跳什麼都沒做——這在真實的 Paperclip 裡代表 CEO 少了哪個工作（提示：拆目標、派工）。
```

**觀察重點**：

- 乾跑時 writer 為什麼沒接任務（T002 依賴 T001）？真跑時為什麼同一拍就接了？
- T002 狀態是否停在 awaiting_approval，approve 後才變 done？
- day-notes.md 是否誠實指出產出裡的可疑處，而不是直接說「沒問題」？

## 教練解說要點

- 代理是員工、Paperclip 是公司：lite 版裡真正「想」的只有 `claude -p` 那一行，其餘全是結構與記帳。
- 你剛剛做的審稿與核准，就是書中說的「放手但不放掉責任」——省下的動手時間要拿來檢查。
- 「完成」只是狀態欄位變了；內容對不對，系統不會告訴你。
- 乾跑是零成本的預演：先看代理會收到什麼提示，再決定要不要花錢。
