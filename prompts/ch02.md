# ch02｜Paperclip 是什麼與不是什麼

## 這章在講什麼

- 網路上有兩個都叫「Paperclip AI」的東西：本書只談 @dotta 的開源框架（github.com/paperclipai、MIT 授權、自己的電腦上跑）；另一個是要註冊、付費的託管服務，毫無關係。
- Paperclip 技術上是 Node.js 伺服器＋React 儀表板，核心是「組織」不是「智慧」：本身不帶語言模型，代理要自己帶。
- 它不是語言模型、不是拖拉方塊的工作流程建構器、也不是開箱即用的公司；它是鷹架，要你填入目標、代理、預算與監督。
- 判斷功能歸屬的公式：真實公司會不會有它？組織圖、預算、核准流程——會；親自寫文字——不會，那是員工的事。
- 選工具要看問題：單一、固定的流程用工作流程工具更穩更便宜；開放目標的多代理協作才需要行政層。

## 作者做過的實驗／例子

- 辨識兩個 Paperclip 的記憶法：看到 github.com/paperclipai、MIT、自己下載啟動 → 開源；看到 sign up、subscription、供應商伺服器 → 託管。
- 託管產品的負評（數字幻覺、版面壞掉）常被算到開源專案頭上——搞混的人等於在評判錯誤的工具。
- 座右銘「如果 OpenClaw 是員工，Paperclip 就是公司」：代理做事，Paperclip 只管多個代理怎麼有秩序地合作。

## 演練

> 說明：本章兩個練習都不呼叫模型（0 次 `claude -p`），只用 init／org／export 與閱讀程式碼。

### 練習 1：用 org／export 拆開「公司體制」與「員工工作」

**目的**：親手確認控制層裡哪些東西屬於公司（結構、規則、帳本），哪些屬於員工（實際產出），以及「腦」其實在外面。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型，不要跑非乾跑的 heartbeat。所有輸出存到 ch02/。
1. PYTHONUTF8=1 python paperclip_lite.py init ch02/co > ch02/init.txt 2>&1
2. PYTHONUTF8=1 python paperclip_lite.py org ch02/co > ch02/org.txt 2>&1
3. PYTHONUTF8=1 python paperclip_lite.py export ch02/co ch02/export.json > ch02/export.txt 2>&1
4. 檢查機密沒有被帶出：在 ch02/export.json 裡搜尋 secrets.json 的值，把搜尋指令與結果存成 ch02/secret-check.txt。
5. ch02/what-belongs-where.md 做一張表，列出公司目錄裡每個檔案（company.json、tasks.json、ledger.json、secrets.json、activity.jsonl、outputs/、locks/），每列填：
   - 這是「公司體制」還是「員工工作」
   - 真實公司裡對應的東西（例：人事檔案、帳本、保險箱、工作成果）
   - 有沒有出現在 export.json
6. 在 paperclip_lite.py 找出唯一會產生「智慧」的地方（函式名與行號），在同一份檔案底部用 3 行說明：如果把 claude -p 換成別的代理（例如另一個 CLI），哪些檔案完全不用改。這就是書中說的「自帶代理」。
```

**觀察重點**：

- outputs/ 是否被歸為員工工作、而且沒出現在匯出裡？secrets 是否確認沒外流？
- 是否正確指出 call_claude 是唯一的「腦」，其餘程式全是行政管理？
- 表格是否用「真實公司會不會有」來判斷，而不是憑感覺？

### 練習 2：兩個 Paperclip 辨識＋工具選型表

**目的**：練習本章兩個判斷：這篇說法講的是哪個產品？這個需求該用哪類工具？
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型、不上網。產出 ch02/identify-and-choose.md，分兩段：
A. 辨識：以下 4 段描述是教練自擬的，請依「網址／授權／是否要註冊付費／在誰的伺服器上跑」逐段判斷屬於「開源框架」「託管產品」或「無法判斷」，每段附判斷依據的關鍵字：
   1)「我從 GitHub clone 下來，npm 裝完在自己筆電上開，MIT 授權，沒註冊任何東西。」
   2)「註冊後選了月費方案，它幫我在雲端產出報表，可是裡面數字對不上。」
   3)「Paperclip AI 很厲害，幫我省了很多時間。」
   4)「登入網站後把代理拖進流程，每月 29 美元起。」
   最後寫一句：第 3 段這種評論為什麼最危險。
B. 選型：列出 3 個自動化需求（例：收到帳單信就記一筆帳、每週自動寫一份學習週報、三個代理分工寫一本電子書的摘要），每個判斷是「單一固定流程」還是「開放目標＋要管成本與責任的多代理」，建議用哪類工具（工作流程建構器／單一 claude -p 腳本／代理協調層），附一句理由與「選錯會怎樣」。
```

**觀察重點**：

- 第 3 段是否被判為「無法判斷」，並說出原因（沒有任何可辨識特徵）？
- 選型是否誠實承認多數單一流程不需要 Paperclip？
- 理由是否回扣本章的「行政層 vs. 工作台」分類？

## 教練解說要點

- 在 lite 版裡，「Paperclip 本身不帶 AI」看得一清二楚：拿掉 call_claude，剩下的全是組織。
- 匯出時機密被濾掉，是「結構可以分享、鑰匙不能」的設計，第 4 章會再談。
- 採用任何網路說法前，先問「它講的是哪一個」；講不出來的評論不能當證據。
- Paperclip 一開始看起來「空」不是缺陷：沒有東西可以管時，行政層本來就沒事做。
