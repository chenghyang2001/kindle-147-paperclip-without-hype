# ch03｜@dotta 與炒作背後的故事

## 這章在講什麼

- Paperclip 出自化名個人 @dotta，2026 年 3 月 2 日發布，前六週破五萬星，6 月中約七萬星、一萬三千個分支；高分支比例代表很多人真的拿去用。
- 起源傳說：@dotta 曾為交易作業同時操控二十多個代理，用一份 HEARTBEATS.md 記錄誰該何時醒來——這就是「心跳」的雛形；但這段故事無法驗證，只能當「看似合理的傳說」。
- 工具從「機房」長出來：鎖、硬性預算上限、完整日誌都是真的跑過幾十個代理的人才會要的東西，所以務實，也有點粗糙。
- 基礎單薄：匿名單人維護、沒有公開團隊與資金，是集中風險；星數衡量關注度，不衡量品質。
- 態度：帶著好奇心試用可以，沒有備援計畫就放進關鍵業務不行。

## 作者做過的實驗／例子

- 讀數字判斷成熟度：約 97.8% TypeScript 代表「出自一人之手」，不代表成熟；v2026.517.0 這種版本號編碼的是日期，不是幾百個穩定版本。
- 觀察者稱它為「包裝在炒作語言裡的架構趨勢」：點子（像公司一樣組織代理）是真的，包裝（零人力公司）是膨脹的。
- 把「有文件佐證」和「看似合理但未證實」分開：交易背景與 HEARTBEATS.md 故事屬於後者。

## 演練

> 說明：本章兩個練習都不呼叫模型（0 次 `claude -p`）。練習 1 需要 `gh` CLI 讀公開 repo（不需付費帳號）；若 `gh` 不能用，就把錯誤存檔並改用文字說明。

### 練習 1：開源專案健康度體檢

**目的**：用實際數字練習「熱門 ≠ 成熟」，並驗證書中「變動很快、要回官方核對」的提醒。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型。所有輸出存到 ch03/。只讀公開資訊，不要 fork、star 或留言。
1. gh repo view paperclipai/paperclip --json name,stargazerCount,forkCount,licenseInfo,updatedAt,primaryLanguage > ch03/repo.txt 2>&1
2. gh api repos/paperclipai/paperclip/contributors --jq '.[0:5] | .[] | "\(.login) \(.contributions)"' > ch03/contributors.txt 2>&1
3. gh release list -R paperclipai/paperclip -L 5 > ch03/releases.txt 2>&1
   （任何一步失敗，例如 repo 改名或不存在，就保留錯誤輸出，不要猜數字。）
4. ch03/health-check.md 做一張表，欄位：指標｜書中數字（2026 年 6 月中）｜你查到的數字｜代表什麼。至少包含 stars、forks、分支比例（forks/stars）、主要語言、授權、前 1 名貢獻者占前 5 名總貢獻的比例、最新版本號格式。
5. 表格下方寫 3 行結論：(a) 熱門程度；(b) 集中風險有多高；(c) 如果要把它放進正式流程，你會先準備哪一個退場方案（例：退回既有的 claude -p 腳本、鎖定版本）。
```

**觀察重點**：

- 數字是否全部來自 ch03/*.txt，查不到的有沒有老實寫「查不到」？
- 是否算出分支比例並解讀它（真實使用 vs. 看熱鬧）？
- 結論是否區分「受歡迎」和「成熟」，並提出具體退場方案？

### 練習 2：寫一份 HEARTBEATS.md，對照 lite 的心跳

**目的**：把起源傳說裡的「報時員」概念具體化，並分清傳說與事實。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型，heartbeat 一律加 --dry-run。所有輸出存到 ch03/。
1. PYTHONUTF8=1 python paperclip_lite.py init ch03/co > ch03/init.txt 2>&1
2. 寫 ch03/HEARTBEATS.md：替 ceo、researcher、writer 各寫一列「多久醒來一次、醒來先看什麼、沒事時做什麼」，間隔要有理由（例：寫手依賴研究員，不必比研究員更勤）。
3. 用乾跑模擬兩拍：
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch03/co --dry-run > ch03/beat1.txt 2>&1
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch03/co --agent ceo --dry-run > ch03/beat2-ceo.txt 2>&1
4. ch03/legend-vs-fact.md 做兩張表：
   A. 本章出現的 6 個說法（例：發布日、星數、交易背景、HEARTBEATS.md、單人維護、97.8% TypeScript），每個標「有公開紀錄可查」或「未證實傳說」，附判斷理由。
   B. 你的 HEARTBEATS.md 每一列，對到 paperclip_lite.py 的哪個函式（例：醒來先看什麼 → pick_task），哪些是 lite 版沒有、只能靠外部排程（cron／工作排程器）補的。
```

**觀察重點**：

- beat1.txt 裡 ceo、writer 是否顯示「沒有可做的任務，繼續睡」，而且沒有任何模型呼叫？
- 傳說與事實是否分得清楚，沒有把交易背景寫成事實？
- 是否發現 lite 版的心跳只有「一拍」，「多久醒一次」要靠外部排程？

## 教練解說要點

- 星數是關注度，分支比例才比較接近「有人在用」；單人維護是風險，不是缺點，要配退場計畫。
- HEARTBEATS.md 的精神是「醒來先看有沒有事，沒事就睡」，lite 版的 pick_task 就是這一步，而且不花錢。
- 研究摘要裡，未證實的說法要標註，不要因為故事好聽就寫成事實。
- 這個專案生於實務：鎖、預算、日誌都是被痛過才加的，下一部會逐一拆開。
