# ch04｜架構總覽

## 這章在講什麼

- Paperclip 約由十二塊積木組成一家「公司」：身分與存取、組織圖、任務系統、心跳、工作環境、治理與核准、預算與成本、例行與排程、擴充套件、機密與儲存、活動日誌、公司可攜性。
- 每塊積木回答的是管理問題，不是 AI 問題：誰能做什麼、誰在做什麼、怎麼不重工、怎麼不失控。
- 防重工分兩層：任務層用「原子簽出＋執行鎖」，工作環境層讓每個代理在自己的 git worktree 作業、檢查後才合併。
- 公司可匯出、匯入，而且匯出時自動濾掉機密；同一套安裝可分隔多家公司。
- 技術上是 TypeScript／Node.js 伺服器＋內嵌 PostgreSQL＋瀏覽器介面，可在本機跑；但它組織工作，不檢查品質。

## 作者做過的實驗／例子

- 圖書館比喻：原子簽出就像同一本書不會同時借給兩個人；「原子」指簽出在單一、不可中斷的一步完成。
- 三個人同時改同一段文字會互相覆蓋；獨立工作副本讓每個代理有自己的工作台。
- 鎖管得了「同一份材料」，管不了兩個代理在內容上各說各話——實質協調仍要靠清楚的目標與人工審查。

## 演練

> 說明：本章兩個練習都不呼叫模型（0 次 `claude -p`），heartbeat 一律乾跑。

### 練習 1：十二塊積木對照表——lite 版有哪些、缺哪些

**目的**：用一份迷你實作當鏡子，把抽象的十二塊積木對到具體程式，順便看出「真正的 Paperclip 多做了什麼」。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型。所有輸出存到 ch04/。
1. PYTHONUTF8=1 python paperclip_lite.py selftest > ch04/selftest.txt 2>&1
2. 通讀 paperclip_lite.py，寫 ch04/twelve-blocks.md，表格 12 列（照本章順序：身分與存取、組織圖與代理、任務與工作系統、心跳執行、工作環境與執行期、治理與核准、預算與成本控制、例行與排程、擴充套件、機密與儲存、活動與事件日誌、公司可攜性），欄位：
   積木｜書中它解決什麼問題（一句）｜lite 版有沒有（有／部分／沒有）｜lite 版在哪（函式名或檔案）｜缺的部分在真實公司會造成什麼麻煩
3. 表格下方：
   (a) 從 selftest.txt 指出 selftest 驗證了哪 4 塊積木；
   (b) 挑 lite 版「沒有」的兩塊，各用 3 行描述你會怎麼最小化補上（只寫設計，不要改 paperclip_lite.py）；
   (c) 一句話說明為什麼「架構越完整，越容易讓人盲目信任」。
```

**觀察重點**：

- 是否誠實標出 lite 版沒有的積木（例如身分與存取、工作環境隔離、擴充套件、排程），而不是硬湊？
- 「部分」的判斷是否有根據（例：預算只有硬停、沒有 80% 警告）？
- 補強設計是否小而可行？

### 練習 2：帶著走的公司——匯出、在新位置重建、確認鑰匙沒跟著走

**目的**：體驗「結構可以分享、機密要重新設定」，以及鎖在任務層的作用。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型，heartbeat 一律加 --dry-run。所有輸出存到 ch04/。
1. PYTHONUTF8=1 python paperclip_lite.py init ch04/co > ch04/init.txt 2>&1
2. PYTHONUTF8=1 python paperclip_lite.py export ch04/co ch04/bundle.json > ch04/export.txt 2>&1
3. 寫 ch04/import_bundle.py（放在 ch04/，不要改 paperclip_lite.py）：讀 bundle.json，在 ch04/co-copy 建出 company.json、tasks.json（每個任務補 status=todo）、ledger.json（每個代理 calls=0、usd=0、paused=False）、outputs/、locks/，但不建 secrets.json；最後印出「缺少機密，請在新環境重新設定」。執行它並把輸出存 ch04/import.txt。
4. PYTHONUTF8=1 python paperclip_lite.py org ch04/co-copy > ch04/copy-org.txt 2>&1
   PYTHONUTF8=1 python paperclip_lite.py status ch04/co-copy > ch04/copy-status.txt 2>&1
5. 任務鎖：在 ch04/co-copy/locks/ 手動建立 T001.lock（內容寫 someone-else），再
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch04/co-copy --agent researcher --dry-run > ch04/locked.txt 2>&1
   刪掉 T001.lock 後再跑一次同樣指令，存 ch04/unlocked.txt。
6. ch04/portability-notes.md：(a) 新舊兩家公司是否完全分開（改其中一家的 tasks.json 會不會影響另一家）；(b) 匯出少了哪些東西（狀態、產出、帳本、機密）以及各自為什麼該少或不該少；(c) locked.txt 與 unlocked.txt 的差別說明了什麼，以及這個鎖擋不住哪一種衝突。
```

**觀察重點**：

- bundle.json 與 co-copy 裡是否都找不到機密值？
- locked.txt 是否顯示「已被別人鎖住，跳過」，unlocked.txt 是否顯示乾跑提示詞？
- 筆記是否點出：鎖只防同一任務被重複接，防不了內容互相矛盾。

## 教練解說要點

- 十二塊積木每一塊都對應真實公司的一個麻煩；看懂缺哪塊，就知道 lite 版不能拿去做什麼。
- 原子簽出的關鍵在「一步完成」：lite 用 O_EXCL 建鎖檔，建得出來才算接到。
- 匯出濾機密不是方便性問題，而是讓範本可以安全流傳的前提。
- 組織得整齊不等於做得好——第 5 章開始看目標怎麼一路傳到代理。
