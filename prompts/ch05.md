# ch05｜組織圖：目標如何抵達代理

## 這章在講什麼

- 組織圖是 Paperclip 的心智核心：最上層 AI CEO、中間部門主管（CTO、CMO…）、底層執行代理，和真實公司一樣。
- 每個任務都知道自己的「家譜」：使命 → 專案 → 代理 → 任務；代理拿到的不只是任務，還有它為什麼存在。
- 角色寫在類似 SKILL.md 的職務說明裡：寫得清楚得到可用的員工，寫得含糊得到含糊的瞎忙。
- 組織圖比流程圖有彈性，因為它允許委派，適合開放目標；但對可預測的固定流程，固定順序往往更穩更便宜。
- 委派的效果只能和被委派的代理一樣好：CEO 拆錯目標，錯誤會沿著鏈往下傳，而且沒人察覺。策略在你設的目標裡，不在組織本身。

## 作者做過的實驗／例子

- 「寫本週電子報」可以一路追到「每月客戶溝通」專案、再追到「提升顧客忠誠度」目標——沒有任何代理在瞎忙。
- 老闆代理常取名 Hermes（眾神的信使），正好對應「分派者與中介者」的角色。
- 「別給代理超過任務所需的層級」：簡單任務不需要硬套一整間公司。

## 演練

> 說明：練習 1 不呼叫模型；練習 2 讓 ceo 真的拆一次目標（1 次 `claude -p`）。整章合計 1 次。

### 練習 1：追目標鏈，找出「瞎忙任務」

**目的**：親眼看到代理收到的提示詞裡有整條目標鏈，以及任務掛錯專案時鏈會斷在哪裡。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型，heartbeat 一律加 --dry-run。所有輸出存到 ch05/。
1. PYTHONUTF8=1 python paperclip_lite.py init ch05/co > ch05/init.txt 2>&1
2. 看 researcher 收到的完整提示詞：
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch05/co --agent researcher --dry-run > ch05/chain-T001.txt 2>&1
3. 在 ch05/co/company.json 的 projects 加一個 P2（title 自訂，例如「讀者問答集」）。然後新增兩個給 ceo 的任務：
   PYTHONUTF8=1 python paperclip_lite.py task ch05/co --title "整理本週 3 則讀者提問" --assignee ceo --project P2 > ch05/task-ok.txt 2>&1
   PYTHONUTF8=1 python paperclip_lite.py task ch05/co --title "研究競品的定價" --assignee ceo --project P9 > ch05/task-orphan.txt 2>&1
   再試一個不存在的代理：
   PYTHONUTF8=1 python paperclip_lite.py task ch05/co --title "測試" --assignee cfo > ch05/task-bad-agent.txt 2>&1
4. PYTHONUTF8=1 python paperclip_lite.py heartbeat ch05/co --agent ceo --dry-run > ch05/chain-ceo.txt 2>&1
   （ceo 會接第一件 todo；看完後把 tasks.json 裡那件改成 done，再乾跑一次存 ch05/chain-ceo-2.txt，看第二件的提示詞。）
5. ch05/goal-chain.md：(a) 把 chain-T001.txt 的提示詞逐行標成「使命／專案／任務／角色說明」；(b) 掛在 P9 的任務提示詞少了哪一行、為什麼工具沒有擋下它；(c) 你會在 cmd_task 加什麼檢查（只寫設計）；(d) 這家公司的 agents 少了哪個人類組織常見的層級，對 3 個代理的小公司來說需不需要補。
```

**觀察重點**：

- 掛錯專案的任務是否照樣能被接、只是提示詞少了「專案」那一行——工具沒擋，要靠人看出來？
- 不存在的代理是否被擋下（有錯誤訊息）？
- 是否回答「層級不超過任務所需」，而不是一律建議加層級？

### 練習 2：讓 CEO 拆一次目標，你來驗收拆解

**目的**：體會「委派不免除檢查」：最該被檢查的，是拆解本身。
**送給練習視窗的提示詞**：

```text
本練習只能有 1 次 claude -p 呼叫。接續練習 1 的 ch05/co；所有輸出存到 ch05/。
1. 先把 ch05/co/tasks.json 裡練習 1 新增的 ceo 任務全部改成 done（避免 ceo 接到舊任務）。
2. PYTHONUTF8=1 python paperclip_lite.py task ch05/co --title "把公司目標拆成 3 個專案、每個專案 2 個任務；每個任務寫明服務哪個專案、交給 researcher 或 writer；用 Markdown 條列" --assignee ceo > ch05/task-plan.txt 2>&1
3. 先乾跑確認 ceo 接到的是這件：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch05/co --agent ceo --dry-run > ch05/plan-dryrun.txt 2>&1
4. 確認無誤後真跑一次：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch05/co --agent ceo > ch05/plan-heartbeat.txt 2>&1（失敗就停，不重試）
5. 讀 ch05/co/outputs/ 底下 ceo 產出的檔案，寫 ch05/decomposition-review.md，逐條檢查每個任務：能否往上追到專案與公司目標？有沒有重複？有沒有和目標無關的瞎忙？派的代理角色對不對？最後給整份拆解 PASS／FAIL＋一句理由，並列出你會刪掉或改掛的任務。
6. 加碼（不呼叫模型）：ch05/my-chain.md 用同樣的「使命 → 專案 → 負責代理 → 任務」樹，畫出使用者自己的一個真實目標（例：拿到 AMR 工程師 offer），並標出一個追不上去的瞎忙任務。
```

**觀察重點**：

- ledger 裡 ceo 是否只多 1 次呼叫？
- 驗收是否真的逐條檢查，而不是整份「看起來不錯」就 PASS？
- 是否發現 lite 版的 ceo 產出只是文字、不會自動變成新任務——真正的委派要靠人或程式再建任務。

## 教練解說要點

- 目標鏈是被「交付」的，不是代理自己想出來的：build_prompt 把公司目標、專案、任務逐行塞進提示詞。
- 工具會照樣接下掛錯專案的任務；鏈斷了沒有警告，所以拆解要有人看。
- 角色描述就是職務說明：role 欄位寫得越具體，產出越不會漫無目的。
- 錯誤會沿著委派鏈往下傳，最便宜的攔截點就在最上層的拆解。
