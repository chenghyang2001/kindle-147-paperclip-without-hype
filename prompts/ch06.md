# ch06｜心跳、例行與排程

## 這章在講什麼

- 心跳是計時守門人：定期或在事件發生時叫醒代理，讓被動助理變成會自己持續工作的員工。
- 每一拍都是同一套樸實流程：先看有什麼新東西 → 檢查自己的交辦與進度 → 決定要不要行動；沒事就再睡。心跳是「檢查邀請」，不是「行動命令」。
- 三種觸發：排程鬧鐘（cron）提供規律、內部事件（前一個代理完成）提供交接、外部訊號（webhook）提供即時反應；webhook 也是一個要上鎖的入口。
- 例行與排程建立在心跳之上，常是最具體的日常效益（每天早上整理詢問、每週五出週報）。
- 每次醒來都可能是一次模型呼叫：節奏太密會悄悄燒錢，「失控迴圈」是最大的實務痛點；節奏「必要時才頻繁，能少就少」。

## 作者做過的實驗／例子

- 交接鏈：研究員做完 → 寫手醒來；寫手做完 → 編輯醒來，不需要人轉交。
- 新手最常犯的錯：為了讓公司看起來「活著」把節奏設得越密越好；收件匣每小時整理一次通常就夠。
- 迷思：「沒事做時心跳不花錢」——不一定，光是「檢查」本身就可能是一次模型呼叫，只有懂得節省的代理才能避免。

## 演練

> 說明：練習 1 跑一次真心跳（researcher＋writer 共 2 次 `claude -p`），其餘乾跑；練習 2 不呼叫模型。整章合計 2 次。

### 練習 1：乾跑、真心跳、空心跳三拍比較

**目的**：看到「同一拍內的事件交接」，以及「沒事的心跳完全不花錢」。
**送給練習視窗的提示詞**：

```text
本練習最多 2 次 claude -p 呼叫。所有輸出存到 ch06/。
1. PYTHONUTF8=1 python paperclip_lite.py init ch06/co > ch06/init.txt 2>&1
2. 第 0 拍（乾跑）：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch06/co --dry-run > ch06/beat0-dry.txt 2>&1
   然後 PYTHONUTF8=1 python paperclip_lite.py status ch06/co > ch06/status0.txt 2>&1
3. 第 1 拍（真跑）：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch06/co > ch06/beat1.txt 2>&1（失敗就停，不重試）
   PYTHONUTF8=1 python paperclip_lite.py status ch06/co > ch06/status1.txt 2>&1
4. 第 2 拍（真跑，但應該沒事）：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch06/co > ch06/beat2.txt 2>&1
   PYTHONUTF8=1 python paperclip_lite.py status ch06/co > ch06/status2.txt 2>&1
5. 把 ch06/co/activity.jsonl 複製成 ch06/activity.txt。
6. ch06/beats.md 做一張表：拍次｜每個代理的動作（睡／乾跑／接任務／完成）｜模型呼叫次數（從 ledger 前後差算）｜任務狀態變化。表下回答：
   (a) 乾跑時 writer 為什麼沒接 T002，真跑時為什麼同一拍就接了（找出 paperclip_lite.py 裡讓這件事發生的程式）——這對應三種觸發裡的哪一種？
   (b) 第 2 拍為什麼 0 次呼叫：lite 版在呼叫模型前做了哪些便宜的檢查？
   (c) 真正的 Paperclip 若「檢查」本身也要問模型，第 2 拍會花多少次呼叫？
```

**觀察重點**：

- beat1.txt 是否 researcher、writer 都完成、ceo 在睡？ledger 是否各多 1 次？
- beat2.txt 是否全部「沒有可做的任務」，ledger 完全沒變？
- (a) 是否找到 cmd_heartbeat 共用同一份 tasks 清單、pick_task 看到 T001 已完成？

### 練習 2：任務鎖與節奏成本試算

**目的**：確認任務鎖擋得住重複接單，並用數字感受「節奏紀律就是預算紀律」。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型，heartbeat 一律加 --dry-run。所有輸出存到 ch06/。
1. PYTHONUTF8=1 python paperclip_lite.py init ch06/co2 > ch06/co2-init.txt 2>&1
2. 模擬「別的代理已經接走」：在 ch06/co2/locks/ 建 T001.lock（內容 other-agent），然後
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch06/co2 --agent researcher --dry-run > ch06/lock-held.txt 2>&1
3. 確認鎖檔還在（ls ch06/co2/locks > ch06/lock-after.txt），刪掉後再乾跑一次存 ch06/lock-released.txt，並再 ls 一次附加到 ch06/lock-after.txt（乾跑完鎖應該已被釋放）。
4. ch06/rhythm-cost.md：
   A. 說明 try_checkout 與 release 的流程，以及為什麼接不到鎖時「不會」誤刪別人的鎖。
   B. 節奏試算表：3 個代理，分別假設心跳每 5 分鐘、每小時、每天 1 次，算每月心跳次數；再分兩種情況算每月模型呼叫上限：(i) 像 lite 版「沒事不呼叫」、每月真正有任務 60 件；(ii) 「檢查也要問模型」。用 ch06/co 的 ledger 實際 usd／次數當單價估月成本（若是 0 就寫 0，並說明為什麼訂閱模式下看不到真實價格）。
   C. 一句話結論：你會替「每天整理收件匣」選哪個節奏、為什麼。
```

**觀察重點**：

- lock-held.txt 是否顯示「已被別人鎖住，跳過」，而且別人的鎖檔沒被刪？
- 試算表是否看出「檢查也要問模型」時，每 5 分鐘一拍的成本差上幾個數量級？
- 結論是否選了「能少就少」的節奏並給理由？

## 教練解說要點

- 心跳是檢查邀請：lite 版先用 pick_task 這種不花錢的檢查決定要不要叫醒「腦」。
- 同一拍內 researcher 一完成、writer 就接手，就是事件驅動交接的最小版本。
- 任務鎖讓「誰在做」只有一個答案；鎖不住內容衝突，但鎖住了重工。
- 失控迴圈的根源是「每一拍都想做點什麼」，下一章用預算撞牆來收尾。
