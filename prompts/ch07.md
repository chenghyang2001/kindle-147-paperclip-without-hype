# ch07｜治理、預算與成本控制

## 這章在講什麼

- 心跳是引擎、治理是煞車；作者認為這是全書實務上最重要的一章：AI 公司是好用工具還是成本陷阱，在這裡決定。
- 硬性預算三段：約 80% 警告、100% 自動停止、只有「董事會」明確且被記錄的決定能拆牆；硬停是對付失控迴圈最有效的保險。
- 核准閘門：有後果的動作代理不能直接做，要送上層或人類簽核——「沒有人類的公司」一談到責任就是虛構。
- 無缺漏的活動日誌服務兩件事：除錯（結果錯了能往回追）與問責（能證明重大步驟確實被核准過）；但日誌只有在有人看時才有用。
- 軟體免費，運作不免費：帳單由代理數量、心跳節奏、任務複雜度、模型選擇四個量決定，而且四個都在你手上。

## 作者做過的實驗／例子

- 最常見的昂貴錯誤：不設上限就開跑「看看會怎樣」——偏偏就是那時候出事；一開始就刻意把預算設緊。
- 80% 警告被作者認為是最有價值的一段：它給你在事情變嚴重之前停下來想一想的那一刻。
- 模型混搭：少數吃重步驟用強模型、大量簡單步驟用便宜模型，每次操作的價差輕易超過十倍。

## 演練

> 說明：練習 1 共 3 次 `claude -p`（researcher 1 次、writer 撞牆前 1 次、董事會解除後 1 次）；練習 2 不呼叫模型。整章合計 3 次。

### 練習 1：把 writer 的預算調低，親手撞牆、核准、再由董事會拆牆

**目的**：完整走一遍「預算硬停 → 核准閘門 → 明確且被記錄的推翻」。
**送給練習視窗的提示詞**：

```text
本練習最多 3 次 claude -p 呼叫；任何一步出錯就停下，不要重試。所有輸出存到 ch07/。
1. PYTHONUTF8=1 python paperclip_lite.py init ch07/co > ch07/01-init.txt 2>&1
2. 把 writer 的 max_calls 從 2 改成 1（只改 ch07/co/company.json，不改 paperclip_lite.py），然後
   PYTHONUTF8=1 python paperclip_lite.py org ch07/co > ch07/02-org.txt 2>&1（確認 writer 顯示「上限 1 次」）
3. 再給 writer 一件不需核准的任務：
   PYTHONUTF8=1 python paperclip_lite.py task ch07/co --title "寫一句 30 字內、讓新手看懂心跳排程的比喻" --assignee writer > ch07/03-task.txt 2>&1
4. 第 1 次呼叫：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch07/co --agent researcher > ch07/04-hb-researcher.txt 2>&1
5. 第 2 次呼叫：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch07/co --agent writer > ch07/05-hb-writer.txt 2>&1
   （writer 會先接 T002，因為它排在前面且 T001 已完成。）
6. 撞牆（不會呼叫模型）：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch07/co --agent writer > ch07/06-hb-writer-wall.txt 2>&1
7. PYTHONUTF8=1 python paperclip_lite.py status ch07/co > ch07/07-status.txt 2>&1
8. 核准閘門：先故意核准還沒做的 T003（應該被拒，指令會以非零結束碼結束，屬正常，照樣往下做），再核准 T002：
   PYTHONUTF8=1 python paperclip_lite.py approve ch07/co T003 > ch07/08-approve-wrong.txt 2>&1
   PYTHONUTF8=1 python paperclip_lite.py approve ch07/co T002 > ch07/09-approve.txt 2>&1
9. 董事會拆牆（明確且留紀錄）：用一段 Python（PYTHONUTF8=1 python -c 或 ch07/board_override.py）一次完成三件事——company.json 裡 writer 的 max_calls 改成 2；ledger.json 裡 writer 的 paused 改回 false；在 activity.jsonl 追加一行 {"ts": 現在時間, "actor": "owner", "action": "board_override", "agent": "writer", "reason": "T003 是一句話的小任務，同意多給 1 次", "new_max_calls": 2}。把這段程式與執行結果存 ch07/10-override.txt。
10. 第 3 次呼叫：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch07/co --agent writer > ch07/11-hb-after-override.txt 2>&1
11. PYTHONUTF8=1 python paperclip_lite.py status ch07/co > ch07/12-status-final.txt 2>&1
    並把 ch07/co/activity.jsonl 複製成 ch07/13-activity.txt。
12. ch07/governance-notes.md：
    (a) 把書中三段（80% 警告／100% 硬停／董事會推翻）各對到你看到的哪個檔案哪一行；lite 版沒有 80% 警告，若要加，你會在 budget_block_reason 前後加什麼判斷（只寫設計）。
    (b) lite 版是在呼叫「之前」檢查預算——用 max_usd 舉例說明這為什麼可能讓實際花費略超過上限。
    (c) T003 被拒核准、T002 被核准，說明核准閘門只放行哪一種狀態。
    (d) 從 13-activity.txt 證明：撞牆、核准、推翻三件事都留下了誰、何時、為什麼。
```

**觀察重點**：

- 06-hb-writer-wall.txt 是否出現「呼叫次數達上限 1 → 暫停，不做事」，ledger 的 writer 呼叫數沒有增加？
- 08 是否被拒（狀態是 todo，不是 awaiting_approval），09 是否成功？
- 推翻是否同時改了上限、解除暫停、留下有理由的紀錄，而不是只偷偷改數字？全程是否剛好 3 次呼叫？

### 練習 2：讀稽核日誌＋帳單四因素試算

**目的**：練習用日誌回答「為什麼會這樣」，並把成本拆成你能控制的四個量。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型，只讀練習 1 留下的 ch07/co。產出 ch07/audit-and-cost.md：
A. 稽核：只看 ch07/13-activity.txt 與 ch07/12-status-final.txt，回答
   1) T002 現在為什麼是 done？誰在什麼時間核准的？
   2) writer 為什麼一度不做事？是誰、以什麼理由讓它恢復？
   3) 列出一件「日誌回答不了」的事（例：T002 被核准前人有沒有真的讀過內容），並提出要多記哪個欄位。
B. 帳單四因素：以 ledger.json 每次呼叫的實際 usd 當「便宜模型單價」（若為 0，改用 1 個單位表示），假設頂級模型是 10 倍。為一家 5 個代理、每天 24 拍心跳的公司，填表比較四種配置的每月呼叫數與相對成本：
   - 每拍都問模型＋全用頂級模型
   - 每拍都問模型＋九成便宜、一成頂級
   - 沒事不問模型（每月 150 件真任務）＋全用頂級模型
   - 沒事不問模型＋九成便宜、一成頂級
   最後一句：四個因素裡，哪一個在這家公司最該先調？
```

**觀察重點**：

- 稽核答案是否全部有日誌行為依據，沒有憑推測？
- 是否看出「日誌記了核准動作，但記不了人有沒有認真審」？
- 試算是否顯示節奏與模型選擇的組合可以差上好幾個數量級？

## 教練解說要點

- 硬停在 lite 版就是 budget_block_reason：呼叫前先看帳本，到上限就把 paused 設成 true，之後每拍都直接拒絕。
- 核准閘門只看狀態：只有 awaiting_approval 才能被 approve，沒做完的事不能被「核准完成」。
- 推翻上限是董事會的權力，但必須是明確動作、寫明理由，否則日誌就失去問責的意義。
- 開跑前先裝煞車：預算設緊、有後果的步驟設核准、定期看日誌——幾分鐘的準備決定它是工具還是陷阱。
