# ch08｜自帶代理：你自己的員工

## 這章在講什麼

- Paperclip 本身不帶任何 AI，是「工具無關」的指揮層：要用哪些代理、哪些模型，由你自己帶進來（Bring Your Own Agent）。
- 代理透過適配器接上：Claude Code、Codex、Cursor、Gemini、命令列（Bash）、通用 HTTP 都能當「員工」。適配器是口譯員，不是老師——它只負責溝通，不讓弱代理變強。
- 金鑰由代理自己帶，費用走你自己在各供應商的帳戶；選哪個代理，同時決定了成本、品質與資料流向。
- 工具無關的反面：你會繼承所選代理的弱點（例如被提示注入），治理只能限損、不能歸零。
- 本機模型與 Clipmart 市集都還在變動：「已宣布」不等於「已可用」，敏感用途前要查第一手來源。

## 作者做過的實驗／例子

- 用人資經理比喻：困難的程式工作交給強的代理、例行瑣事交給便宜模型、特殊任務找專門工具，依需求與預算組隊。
- 以 OpenClaw 當 HTTP 適配器的象徵範例，說明幾乎任何外部服務都能被「叫得動」，但交出來的品質完全看那個代理本身。
- 注意框：外洩的金鑰既是資安風險也是成本風險，撿到的人可以拿你的帳單跑模型，所以金鑰只能進機密管理。

## 演練

> 說明：本章兩個練習合計最多 3 次 `claude -p` 呼叫（練習 1 兩次、練習 2 一次）。所有產出放 `ch08/`，公司目錄放 `ch08/co`。

### 練習 1：同一份指派、不同員工——比較 haiku 與 sonnet 寫手

**目的**：親眼看到「適配器只負責溝通、不負責品質」：同一個任務、同一套提示詞，換一個模型當寫手，產出品質就不同。
**送給練習視窗的提示詞**：

```text
本練習最多 2 次 claude -p 呼叫（兩次各一個寫手心跳），其餘都用乾跑。
1. 建兩家一模一樣的公司：
   PYTHONUTF8=1 python paperclip_lite.py init ch08/co-haiku
   PYTHONUTF8=1 python paperclip_lite.py init ch08/co-sonnet
   把兩邊 tasks.json 的 T002 都改成 "depends_on" 拿掉、"needs_approval": true，標題改成「用 200 字向台灣工程師解釋什麼是 AI 代理的『自帶代理（Bring Your Own Agent）』原則，舉一個例子」，讓寫手不必等研究員。
   只把 ch08/co-sonnet/company.json 裡 writer 的 "model" 改成 "sonnet"，其他完全不動。
2. 兩邊先乾跑確認提示詞一字不差：
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch08/co-haiku --agent writer --dry-run > ch08/dryrun-haiku.txt 2>&1
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch08/co-sonnet --agent writer --dry-run > ch08/dryrun-sonnet.txt 2>&1
   用 diff 比較兩檔，把 diff 結果存 ch08/dryrun-diff.txt（應該沒有差異）。
3. 各跑一次真心跳（各 1 次呼叫），只叫 writer：
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch08/co-haiku --agent writer > ch08/run-haiku.txt 2>&1
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch08/co-sonnet --agent writer > ch08/run-sonnet.txt 2>&1
   再把兩邊 status 輸出附加到同一檔。
4. 寫 ch08/compare.md：
   (a) 表格比較兩份 outputs/T002.md：字數、是否切題、例子是否具體、有沒有說錯的地方、花費（從 ledger 讀）；
   (b) 用一段話說明：為什麼提示詞完全一樣、品質卻不同——對應書中「適配器是口譯員，不是老師」；
   (c) 如果這是正式公司，你會讓哪個模型當寫手、理由（成本／品質／資料流向三點都要寫）。
不要核准任何任務。
```

**觀察重點**：

- dryrun-diff.txt 是否真的沒有差異？只差在模型，比較才公平。
- 是否只呼叫 2 次（看兩邊 ledger 的 calls）？
- compare.md 有沒有用到實際產出的具體句子，而不是泛泛而談？

### 練習 2：複製一份 lite，加一種「命令列員工」

**目的**：理解適配器的意思：同一套「指派＋回報」流程，可以接完全不同構造的員工。本練習加一個不用模型、只跑本機指令的 Bash 型代理，與模型型代理並存。
**送給練習視窗的提示詞**：

```text
本練習最多 1 次 claude -p 呼叫。不要修改 practice/paperclip_lite.py 本體。
1. 複製 paperclip_lite.py 成 ch08/paperclip_byoa.py。在副本裡讓代理多一個欄位 "adapter"：
   - "claude"（預設，沿用 call_claude）
   - "shell"：不呼叫模型，改用 subprocess 執行任務裡的 "command" 欄位（只允許白名單指令：python --version、git --version、node --version 三選一，其他一律拒絕並記錯誤），把 stdout 當成產出、花費記 0。
   在 heartbeat_one 依 agent 的 adapter 分流；其他邏輯（任務鎖、預算、核准、活動紀錄）不要動。
2. PYTHONUTF8=1 python ch08/paperclip_byoa.py init ch08/co
   在 ch08/co/company.json 加一個代理 {"id":"ops","role":"維運員：回報本機工具版本","reports_to":"ceo","model":"none","adapter":"shell","max_calls":2,"max_usd":0}，ledger.json 也補 ops 一列。
   用 task 指令新增兩個任務給 ops，再手動在 tasks.json 為它們加 "command"：一個 "python --version"、一個 "rm -rf ch08"（用來測白名單會拒絕）。
3. 執行並存檔：
   PYTHONUTF8=1 python ch08/paperclip_byoa.py heartbeat ch08/co --agent ops > ch08/byoa-run.txt 2>&1   （跑兩次，讓兩個任務都被嘗試）
   PYTHONUTF8=1 python ch08/paperclip_byoa.py heartbeat ch08/co --agent researcher >> ch08/byoa-run.txt 2>&1   （這是唯一一次真的呼叫模型）
   PYTHONUTF8=1 python ch08/paperclip_byoa.py status ch08/co >> ch08/byoa-run.txt 2>&1
4. 寫 ch08/byoa-notes.md：
   (a) 你改了哪幾個函式、各幾行；
   (b) shell 員工和 claude 員工在帳本、活動紀錄上看起來有什麼一樣、什麼不一樣；
   (c) 被拒絕的 rm 指令在 activity.jsonl 留下什麼紀錄；
   (d) 一句話說明：為什麼「接進一個權限很大的員工，公司就一起承擔它的風險」，而白名單在這裡扮演什麼角色。
```

**觀察重點**：

- 本體 paperclip_lite.py 有沒有被動到（應該沒有）？
- 危險指令是否真的被白名單擋下、而不是被執行？
- 是否只有 researcher 那一次呼叫了模型？

## 教練解說要點

- 「我要用哪個 AI」同時是金錢、品質與資料保護三個決定，不是技術小插曲。
- 適配器讓所有員工都叫得動，但聰明程度屬於員工，不屬於公司；換員工要靠比較實際產出來判斷。
- 接進權限越大的員工，爆炸半徑越大；白名單、最小權限是你自己要加的，適配器不會幫你加。
- 金鑰永遠進機密管理；本練習的 lite 版走 `claude -p` 訂閱，連金鑰都不需要碰。
