# ch09｜你的第一家 AI 公司：逐步實作

## 這章在講什麼

- 第一家公司分五步：安裝、建小型組織圖、接上自己的代理、裝好煞車、給明確目標並觀察。刻意從小開始：一個 CEO、兩個員工、一份很緊的預算。
- 安裝有快速啟動（一行 `onboard --yes`）與手動（clone → install → dev）兩條路；兩個開關要刻意選：可連線範圍預設只在本機，遙測預設開啟、應在一開始就關。
- 組織圖每個角色都要寫「存在目的」與「怎樣算做得好」；金鑰只進機密管理，三個代理先用同一個便宜可靠的模型。
- 煞車不是選配：硬性停止的總預算、所有對外動作要審批、盯日誌——這是「受控實驗」與「空白支票」的差別。
- 最重要的一步屬於人：檢查結果的事實、來源與可用性。「完成」不等於「正確」。

## 作者做過的實驗／例子

- 範例目標：「針對主題 X，寫一篇研究充分、附來源的部落格文章草稿」，觀察 CEO 怎麼拆工、分給研究員與寫手。
- 前置條件白話版：Node.js 20 以上、pnpm 約 9.15 以上，資料庫是內嵌的 PostgreSQL、不用自己裝；軟體免費，花錢的是員工的工作。
- 提醒：別被即時畫面催眠，重點是最終結果的品質；預設值是為方便而調，不是為謹慎而調。

## 演練

> 說明：本章不安裝官方 `paperclipai`，用 `paperclip_lite.py` 把書中五步完整走一遍。全章最多 3 次 `claude -p` 呼叫（練習 1 的一次真心跳＝CEO、研究員、寫手各 1 次，約 1 分鐘）；練習 2 不呼叫模型。產出放 `ch09/`，公司目錄放 `ch09/co`。

### 練習 1：用 paperclip_lite 走完五步，寫查核報告

**目的**：親手把「安裝 → 組織圖 → 接代理 → 煞車 → 目標與觀察」做一次，最後用人工查核決定要不要核准草稿。
**送給練習視窗的提示詞**：

```text
本練習最多 3 次 claude -p 呼叫，只發生在步驟五的「一次」真心跳。每一步的指令輸出都要存成 ch09/ 底下的 .txt。

步驟一（安裝）：
  PYTHONUTF8=1 python paperclip_lite.py selftest > ch09/step1-install.txt 2>&1
  PYTHONUTF8=1 python paperclip_lite.py init ch09/co >> ch09/step1-install.txt 2>&1

步驟二（組織圖）：寫 ch09/setup_co.py（json 讀寫即可），把 ch09/co 改成書中的迷你公司：
  - company.json："name" 改成「第一家 AI 公司（ch09）」；"goal" 改成「針對主題『Node.js 20 的三個重要新功能』，寫一篇研究充分、附來源的部落格文章草稿」；"projects" 只留 P1，標題「部落格草稿：Node.js 20 的三個重要新功能（附來源）」。
  - 三個代理 ceo／researcher／writer 都用 "model": "haiku"，"role" 都要寫「職責＋做得好＝…」，例如 researcher：「研究員：列出事實與官方來源網址。做得好＝每項可追溯，不確定的標『未確認』」。
  - tasks.json 換成三個任務（status 都是 todo）：
      T001 ceo：「把公司目標拆成給研究員與寫手的兩段具體指示（各 3～5 行）」，needs_approval false
      T002 researcher，depends_on T001：「依 CEO 指示列出 Node.js 20 的 3 個重要新功能，每項一句說明＋一個官方來源網址；不確定的標『未確認』」，needs_approval false
      T003 writer，depends_on T002：「依研究員的重點寫 300 字內的部落格草稿，文末列出來源網址；沒有來源的內容不要寫」，needs_approval true（發布是對外動作）
  - ledger.json 三個代理都歸零。
  執行 setup_co.py 後跑 org，輸出存 ch09/step2-org.txt。

步驟三（接代理與金鑰）：
  - 把 ch09/co/secrets.json 改成 {"MODEL_ACCESS_KEY": "placeholder-not-a-real-key"}（假值，只為了示範機密放哪裡）。
  - 執行 grep -rn "placeholder-not-a-real-key" ch09/co/company.json ch09/co/tasks.json，結果（應為沒有命中）存 ch09/step3-secrets.txt。
  - 在同一檔用兩三行說明：lite 版的代理走 claude -p（Max 訂閱），程式會拿掉 ANTHROPIC_ 開頭的環境變數；正式 Paperclip 的金鑰要放在它的機密管理裡。

步驟四（煞車）：
  - 三個代理的 "max_calls" 都設 1、"max_usd" 都設 0.10（硬性停止），再跑一次 org 附加到 ch09/step4-brakes.txt。
  - 先乾跑看提示詞，不花錢：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch09/co --dry-run >> ch09/step4-brakes.txt 2>&1
    （乾跑只會看到 CEO 的提示詞；研究員與寫手因為依賴還沒完成，會顯示「繼續睡」。）

步驟五（給目標並觀察）：
  - 真心跳一次（這是唯一會呼叫模型的地方，約 1 分鐘，3 次呼叫）：
    PYTHONUTF8=1 python paperclip_lite.py heartbeat ch09/co > ch09/step5-heartbeat.txt 2>&1
  - PYTHONUTF8=1 python paperclip_lite.py status ch09/co >> ch09/step5-heartbeat.txt 2>&1
  - 再乾跑一次心跳，確認硬性停止生效（應顯示每個代理「呼叫次數達上限 1 → 暫停」）：
    PYTHONUTF8=1 python paperclip_lite.py heartbeat ch09/co --dry-run > ch09/step5-hardstop.txt 2>&1
  - 匯出並確認機密沒有帶出去：
    PYTHONUTF8=1 python paperclip_lite.py export ch09/co ch09/export.json，再 grep -c "placeholder-not-a-real-key" ch09/export.json，兩者輸出存 ch09/step5-export.txt。

人工查核（最重要）：
  - 讀 ch09/co/outputs/T001.md、T002.md、T003.md，看 CEO 怎麼拆工、研究員交了什麼、寫手有沒有加料。
  - 把 T003.md 裡的每個網址用 curl -s -o /dev/null -w "%{http_code}" -L --max-time 15 <網址> 檢查，結果存 ch09/url-check.txt（這不是模型呼叫）。
  - 寫 ch09/check-report.md：
      (a) 表格：每個事實主張｜出現在哪個輸出｜來源網址｜HTTP 狀態｜你判斷對不對｜理由；
      (b) 網址回 200 是否就代表內容支持那句話？挑一條用你自己的知識說明；
      (c) 寫手有沒有寫出研究員沒給的內容；
      (d) 結論：核准或不核准。只有查核通過才執行 PYTHONUTF8=1 python paperclip_lite.py approve ch09/co T003（輸出附加到 check-report.md 底部）；不通過就保持 awaiting_approval，寫出要退回修改的地方。
```

**觀察重點**：

- 一次心跳內，CEO → 研究員 → 寫手是否依依賴順序全部做完，T003 停在 awaiting_approval？
- 帳本是否每人剛好 1 次、第二次乾跑全部被硬性停止擋下？
- 查核報告是否區分「網址存在」與「內容正確」？核准是否有根據，而不是因為代理說完成？

### 練習 2：書中步驟 vs lite 版對照表（不安裝官方版）

**目的**：把書中真正的安裝與安全開關，和 lite 版的對應零件逐條對齊，知道 lite 省略了什麼、正式上線時要補什麼。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型、不安裝 paperclipai、不連網下載任何套件。
1. 檢查本機前置條件並存檔：node -v、pnpm -v（沒有就記「未安裝」，不要去裝），輸出存 ch09/prereq.txt。
2. 確認 lite 版沒有開任何網路連接埠：在練習 1 跑完之後，用 netstat -ano | findstr LISTENING（Git Bash 可用 netstat -ano | grep LISTENING）看有沒有 python 程序在監聽，結論寫進 ch09/prereq.txt。
3. 寫 ch09/official-vs-lite.md，一張表，至少下列 10 列：
   書中步驟或設定｜官方 Paperclip 怎麼做（依書）｜lite 版對應（指令或檔案）｜lite 省略或簡化了什麼｜正式使用要注意什麼
   必含：快速啟動 npx paperclipai onboard --yes、手動 git clone／pnpm install／pnpm dev、Node.js 20／pnpm 9.15、內嵌 PostgreSQL、儀表板、可連線範圍（--bind lan／--bind tailnet）、遙測預設開啟、組織圖、機密管理、硬性預算、對外動作審批、日誌。
4. 表格下方用 3～5 句寫：如果下週要真的裝官方版，第一次啟動後你會依序檢查哪三件事、各用什麼方法確認。
```

**觀察重點**：

- 對照表是否誠實寫出 lite 沒有的東西（儀表板、資料庫、遙測、網路綁定）？
- 有沒有守住「不安裝、不下載」？
- 第一次啟動的三件檢查是否具體到可操作（例如查監聽位址、查遙測環境變數）？

## 教練解說要點

- 五步裡第四步（煞車）要在任何東西開跑前完成；本練習先乾跑、再跑一次，就是受控實驗的最小版。
- 從小開始：三個代理、同一個便宜模型、每人 1 次上限，一次心跳就能看完整個拆工流程。
- 「完成」只是狀態，不是品質；核准閘門是你負責任地說「我同意」的位置，要有查核報告撐腰。
- 預設值為方便而調：可連線範圍與遙測第一次啟動就要確認，不要「之後再說」。
