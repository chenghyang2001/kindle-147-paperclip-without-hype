# ch10｜使用案例與自己的實驗

## 這章在講什麼

- Paperclip 適合「大量相似、容易拆解、可驗證、會重複」的任務；可靠性、判斷力與責任重要的地方，重心就回到人。
- 一人公司的誠實解讀：不是「沒有人的公司」，而是「一個人用 AI 員工取代許多例行工作，重要決定留在自己手上」。
- 內容管線、協調多個寫程式代理、重複性營運任務是主要案例；其中例行營運最不起眼、風險最低，是最好的入口。
- 自主陌生開發信是地雷：品質與法律都有風險，凡未經人核准的東西都不要讓代理往外送。
- 自己做一次實驗會學到兩件事：協調看起來多流暢，以及要讓「完成」變成「正確」需要多少檢查。

## 作者做過的實驗／例子

- 交易桌是整個專案的起源：大量平行的程式與分析代理，需要任務鎖、獨立工作副本、硬性預算與完整日誌才馴服得了。由此得出經驗法則：越像「許多相似、邊界清楚、可平行、可驗證」的任務，越適合。
- 流傳的「週末無人公司」失敗實測出現幻覺統計與破版，但對象是同名的託管商業版，不是開源版；不過「會自動跑≠可以發佈」的教訓對兩者都成立。
- 「從筆記 App 到年營收百萬」的範例被拆成真實的部分（例行事務可委派）與誇大的部分（決策、信任、法律無法被編排保證）。

## 演練

> 說明：本章練習 1 最多 2 次 `claude -p` 呼叫，練習 2 不呼叫模型。產出放 `ch10/`，公司目錄放 `ch10/co`。

### 練習 1：設計並執行一個「幻覺統計偵測」小實驗

**目的**：照科學實驗的格式（假設 → 設計 → 執行 → 量測 → 結論）做自己的第一個實驗，親眼量出「自動跑完」與「可以發佈」之間差多少。
**送給練習視窗的提示詞**：

```text
本練習最多 2 次 claude -p 呼叫（一次心跳：研究員 1 次＋寫手 1 次）。
1. 先寫 ch10/experiment-plan.md（動手前就寫好）：
   - 假設：例如「沒有上網工具的研究員被要求附統計數字時，至少有一個數字或來源無法查證」。
   - 設計：用 paperclip_lite 的內容管線（研究員 → 寫手），主題「台灣近年電動機車的市場概況」，要求研究員給 3 個統計數字並附來源網址。
   - 量測指標：數字總數、附來源的數量、網址回 200 的數量、你能確認數字確實出現在來源中的數量、寫手是否加了研究員沒給的數字。
   - 停止條件與預算：只跑一次心跳、每個代理 max_calls 1。
2. PYTHONUTF8=1 python paperclip_lite.py init ch10/co，然後改 ch10/co：
   - company.json 的 goal 改成「每週產出一則附來源的台灣電動機車市場短訊」，researcher、writer 的 max_calls 都改 1。
   - tasks.json 的 T001 標題改成「列出台灣電動機車市場的 3 個統計數字（年份、數字、單位），每個附一個來源網址；不確定的標『未確認』」；T002 標題改成「依 T001 寫 150 字社群短訊，數字只能用 T001 給的」，保留 depends_on 與 needs_approval true。
   先乾跑存 ch10/dryrun.txt：PYTHONUTF8=1 python paperclip_lite.py heartbeat ch10/co --dry-run > ch10/dryrun.txt 2>&1
3. 真心跳一次並存檔：
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch10/co > ch10/run.txt 2>&1
   PYTHONUTF8=1 python paperclip_lite.py status ch10/co >> ch10/run.txt 2>&1
4. 量測：把 outputs/T001.md 的網址逐一用 curl -s -o /dev/null -w "%{http_code}" -L --max-time 15 <網址> 檢查，存 ch10/url-check.txt；能打開的頁面，用 curl 抓下來 grep 看數字是否真的出現（不是模型呼叫）。
5. 寫 ch10/experiment-result.md：指標表（照步驟 1 的指標填實際數字）、假設成立或不成立、一段話說明這個結果對「內容管線能不能無人發佈」的意義。T002 不要核准。
```

**觀察重點**：

- 實驗計畫是否在執行前就寫好、指標可量測（而不是事後找理由）？
- 量測是否分清「網址存在」與「數字真的在來源裡」？
- 結論是否回到本章「會自動跑≠可以發佈」，而不是只說「AI 很厲害／很爛」？

### 練習 2：我的使用案例適配度評分表

**目的**：用本章的尺（定義清楚、容易驗證、會重複、是否對外、是否有法律或信任份量）幫自己的工作挑出適合交給 AI 公司的入口。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型。
寫 ch10/use-case-scores.md：
1. 列出 6 件你（使用者）實際常做的工作，至少包含：每日信件摘要、購物比價、寫週報、回覆求職或廠商訊息、整理讀書筆記、一件涉及金錢或合約的事。
2. 表格欄位：工作｜定義清楚 0～2｜容易驗證 0～2｜會重複 0～2｜對外？｜法律／信任份量？｜總分｜建議（全自動／代理準備＋人決定／不適合）｜理由一句。
3. 依總分排序。對外或有法律份量的工作，不論分數多高，建議欄最多只能是「代理準備＋人決定」。
4. 挑出排名第一的工作，寫 5 行以內的「如果用 paperclip_lite 做，組織圖與任務會長怎樣」（代理、任務、哪個任務要 --approval）。
5. 最後一段：本章「一人公司」的誠實解讀，套到你自己身上是什麼意思（3 句以內）。
```

**觀察重點**：

- 是否遵守「對外或有法律份量就要人核准」的上限規則？
- 排名第一的是否像本章說的例行營運任務（低風險、可驗證）？
- 組織圖草案是否小而具體？

## 教練解說要點

- 好的實驗先寫假設與指標再跑；否則看到流暢的協調畫面，很容易被說服。
- 幻覺統計不是某個產品的錯，是任何沒人檢查的 AI 鏈條的通用風險。
- 挑使用案例用一把簡單的尺：越清楚、越好驗證、越常重複，越適合；越需要判斷與負責，越要留給人。
- 看到負評先確認講的是哪個同名版本，但教訓本身仍要認真看待。
