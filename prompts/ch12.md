# ch12｜生態系與競爭

## 這章在講什麼

- 協調 AI 代理有幾個流派：圖派（定義節點與連線，哪一步接哪一步）、角色派（帶角色設定的代理像專案小組合作）、對話派（代理彼此交談、來回傳任務）、以滑鼠串流程的大型自動化平台，以及 Paperclip 的呈報線派。
- 社群口訣「圖等於流程、角色等於團隊、Paperclip 等於呈報線」講的是「不同」，不是「誰比較好」。
- Paperclip 沒有任何單一功能獨一無二，特別的是組合：組織圖是核心、預算與治理是內建構件、徹底工具無關、好記的「公司」隱喻。
- 這個組合只在「開放目標、許多代理、同時有真實成本與責任風險」三者並存時才划算；固定可預測的流程，精簡的序列工具更穩更便宜。
- 領域在 2025／2026 才出現、每月都在變：綁定原則，不綁定品牌。

## 作者做過的實驗／例子

- 作者刻意不點名競品，只描述各流派的代表；並提到已有一本談用 Paperclip 打造「零員工」公司的競爭書籍，當作熱潮的徵兆。
- 「零人力」群組裡許多專案比 Paperclip 更實驗性；活動多、承諾多代表市場熱，不代表市場成熟。
- 兩度注意框：別被動聽的隱喻引誘，以為某工具全面勝出；依任務選工具，而不是依最漂亮的故事選。

## 演練

> 說明：本章兩個練習都不需要呼叫模型（合計 0 次 `claude -p`），全部用乾跑。產出放 `ch12/`。

### 練習 1：生態系比較表＋我的問題分類

**目的**：把五種協調流派放在同一張表上比較，再把自己的實際工作分類，看看哪些其實根本不需要「AI 公司」。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型、不上網查資料（只用書中描述與你已知的概念）。
1. 寫 ch12/ecosystem-table.md，一張表，列是五個流派：圖派、角色派、對話派、自動化平台、呈報線派（Paperclip）。欄位：
   核心心智模型｜你要定義什麼｜最適合的問題｜不適合的問題｜預算／審批是內建還是要自己加｜工具綁定程度｜在 paperclip_lite 裡有沒有對應零件（有的寫函式名）
   表格最後加一列「最精簡替代方案：單一腳本＋排程」，同樣填完。
   註明「資料截至 2026-11（依本書描述，未逐一查證各工具現況）」。
2. 寫 ch12/my-problems.md：列出 5 個你想自動化的工作（可沿用 ch10/use-case-scores.md 的項目），每個標「流程／團隊／呈報」其中一類，寫一句理由，再寫「最精簡可行工具」（單一腳本、排程、單一代理、多代理呈報）。
3. 最後一段：這 5 個裡面，有幾個真的同時符合「開放目標＋許多代理＋真實成本與責任風險」？結論是什麼？
```

**觀察重點**：

- 比較表是否寫出每一派的「不適合」，而不是只誇 Paperclip？
- lite 對應欄是否真的對得上程式（例如 `org_lines`、`try_checkout`、`budget_block_reason`、`cmd_approve`）？
- 分類結果是否多數落在「流程」，誠實反映本章的結論？

### 練習 2：同一件事，序列腳本 vs 呈報線——乾跑比一比

**目的**：用最直接的方式體會「固定流程用序列工具更穩」：把 lite 的「研究員 → 寫手」流程改寫成一支純序列腳本，兩邊都只乾跑，比較複雜度與各自缺什麼。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型，兩邊都只乾跑。
1. PYTHONUTF8=1 python paperclip_lite.py init ch12/co
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch12/co --dry-run > ch12/lite-dryrun.txt 2>&1
2. 寫 ch12/sequence_pipeline.py（不 import paperclip_lite）：一個固定的兩步序列，步驟一組研究員提示詞、步驟二組寫手提示詞（寫手提示詞放「〈步驟一的產出〉」占位），加 --dry-run 參數時只印出兩段提示詞與「會呼叫 claude -p 2 次」，不加參數時直接結束並提示「本練習只允許乾跑」。
   PYTHONUTF8=1 python ch12/sequence_pipeline.py --dry-run > ch12/sequence-dryrun.txt 2>&1
3. 寫 ch12/sequence-vs-lite.md：
   - 表格比較：程式行數（wc -l）、要設定的檔案數、有沒有任務鎖、有沒有每個代理的預算上限、有沒有核准閘門、有沒有活動紀錄、可不可以加第三個代理、失敗時怎麼重跑；
   - 結論：「每週產出一篇短文」這件事，你會選哪一種？什麼條件改變時你會換成另一種？
   - 一句話把本章口訣用在這個例子上。
```

**觀察重點**：

- 兩邊是否都只乾跑、沒有任何模型呼叫？
- 比較是否誠實：序列腳本更短更好懂，但治理零件全部要自己補？
- 「什麼條件下換工具」是否具體（例如代理數變多、目標變開放、開始動到錢或對外）？

## 教練解說要點

- 先分類自己的問題，再挑工具；多數日常自動化是固定流程，一支腳本＋排程就夠。
- Paperclip 的價值在組合與一致性，不在任何單一功能；組合越大，也代表要學、要維護的越多。
- 比較表要寫「不適合什麼」，否則只是在替喜歡的工具找理由。
- 原則（預算、審批、最小權限、查核）可以帶著走，換到任何工具都適用；品牌與數字要標註截至日期。
