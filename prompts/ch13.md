# ch13｜展望、結語與附錄

## 這章在講什麼

- 三個可預見的走向：可靠性成為關鍵問題、重隱私的本機運作越來越重要、專案根基（匿名個人維護）是否能長久。
- 瓶頸是可靠性：編排能組織工作，卻不保證品質；目前確認「完成＝正確」的權威是人類，而且是可預見未來的常態。
- 今天就能帶走的三件事：像帶領勞動力一樣帶領代理的思考框架、工具逼你養成的紀律（從小開始、緊預算、先審批、查結果、敏感資料留本機、記版本）、人不會變多餘而是往上移成指揮者與負責人。
- 附錄把全書濃縮成可用的工具：五步建公司流程、術語表、三角色組織圖範本、11 項安全與控制檢查清單、常見問題。
- 所有發現都當成「截至今天」，記下版本、模型與設定。

## 作者做過的實驗／例子

- 誠實總結算：2026 年夏天的 Paperclip 年輕、迷人、未完成；「完全自己運轉的公司」現在不是、可預見的未來也不會是，它實際上是一套組織與監督工具。
- 組織圖範本的擴編原則：只有迷你公司穩定交出可用成果後才加角色，例如負責品質的「編輯」代理——它補充人類檢查，而不是取代。
- 常見問題裡反覆回到同一句：出事誰負責？你。

## 演練

> 說明：本章練習 1 不呼叫模型，練習 2 最多 1 次 `claude -p` 呼叫。兩個練習都會用到 ch09 建好的 `ch09/co`（只讀，不修改）；如果還沒做 ch09，先回去做 ch09 練習 1。產出放 `ch13/`，公司目錄放 `ch13/co`。

### 練習 1：上線前檢核清單——拿 ch09 的公司實際勾一次

**目的**：把附錄的 11 項安全與控制檢查變成自己的上線前清單，並用證據逐項檢查一家真的跑過的公司。
**送給練習視窗的提示詞**：

```text
本練習不呼叫模型，不修改 ch09/ 底下任何檔案。
1. 收集證據並存 ch13/evidence.txt：
   - claude --version、python --version 的輸出；
   - PYTHONUTF8=1 python paperclip_lite.py org ch09/co 與 status ch09/co 的輸出；
   - grep -n "tools\|STRIP_ENV\|tempfile.gettempdir" paperclip_lite.py 的輸出；
   - netstat -ano | grep LISTENING 中有沒有 python 程序的結論；
   - ch09/co/activity.jsonl 最後 5 行。
2. 寫 ch13/prelaunch-checklist.md，表格 11 列（依本書附錄的 11 個面向：本機執行、遙測、最小權限、硬性預算、對外審批、金鑰在機密管理、結果先查、個資本機、不做陌生開發、應變計畫、記錄版本與設定）。欄位：
   檢查項｜ch09/co 的狀態（是／否／不適用）｜證據（evidence.txt 的哪幾行或哪個檔）｜若是「否」，修正動作
3. 表格下方寫「版本紀錄」一段：日期、claude CLI 版本、使用的模型、paperclip_lite.py 的行數與 sha256（用 sha256sum 算），並註明「以上為截至今天的狀態」。
4. 最後一段：11 項裡哪一項是 lite 版做不到、只有正式上線時才會遇到的？為什麼？
```

**觀察重點**：

- 每一項是否都有可回溯的證據，而不是「應該有」？
- 有沒有誠實標出「否」或「不適用」（例如應變計畫、遙測在 lite 不存在）？
- 版本紀錄是否完整到別人可以重現？

### 練習 2：我的 30 天行動計畫＋加一個「編輯」代理試水溫

**目的**：照附錄的擴編原則，先用一次小實驗看「編輯代理只能補充、不能取代人類查核」，再寫出接下來 30 天怎麼負責任地使用這類工具。
**送給練習視窗的提示詞**：

```text
本練習最多 1 次 claude -p 呼叫（只有編輯代理的一次心跳）。
1. 把 ch09/co 整個複製成 ch13/co（cp -r），之後只改 ch13/co。
2. 在 ch13/co/company.json 加一個代理：
   {"id":"editor","role":"編輯：逐句比對草稿與研究重點，列出沒有根據或可能錯誤的句子。做得好＝每個問題都指出是哪一句、為什麼","reports_to":"ceo","model":"haiku","max_calls":1,"max_usd":0.10}
   ledger.json 補 editor 一列（calls 0、usd 0、paused false）。
   用 task 指令新增任務給 editor：「審查 T003 草稿，列出沒有根據或可能錯誤的句子」，然後在 tasks.json 為這個新任務加 "depends_on": "T003"。
3. 先乾跑再真跑，只叫 editor：
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch13/co --agent editor --dry-run > ch13/editor-dryrun.txt 2>&1
   PYTHONUTF8=1 python paperclip_lite.py heartbeat ch13/co --agent editor > ch13/editor-run.txt 2>&1
   把編輯的產出檔內容附加到 ch13/editor-run.txt。
4. 寫 ch13/editor-vs-human.md：把編輯代理找到的問題，和你在 ch09/check-report.md 自己查到的問題並排比較：雙方都抓到的、只有編輯抓到的、只有你抓到的。注意：編輯只看得到 T003（寫手產出），看不到研究員的 T002，這會漏掉什麼？
5. 寫 ch13/30-day-plan.md：
   - 第 1 週：挑一件 ch10/use-case-scores.md 排名最高的例行工作，定義可檢查的完成條件；
   - 第 2 週：用最小編制跑起來（寫出預算上限、哪些動作要核准、日誌放哪）；
   - 第 3 週：每天抽查結果，記錄「完成但不正確」的次數；
   - 第 4 週：決定擴編、維持或停止，寫出判斷標準（數字門檻）；
   - 每週都要有一行「版本與設定紀錄」；
   - 最後列 3 件「無論工具怎麼變都會留著用」的紀律。
```

**觀察重點**：

- 是否只複製、沒有動到 ch09/ 原檔？是否只呼叫 1 次？
- 編輯代理與人工查核的比較是否具體到句子？有沒有看出「編輯只看得到它拿到的上游」這個盲點？
- 30 天計畫的每週是否都有可檢查的完成條件與數字門檻？

## 教練解說要點

- 未來的關鍵問題不是 AI 公司能多大，而是無人監督時有多可靠；在那之前，人就是品質權威。
- 上線前清單要逐項附證據，「應該有」不算有；做不到的項目要誠實標「否」並寫修正動作。
- 加一個編輯代理是補強，不是取代：它只看得到被交付的內容，看不到被省略的東西。
- 帶走的是紀律與思考框架：從小開始、緊預算、先審批、查結果、敏感資料留本機、記版本——換任何工具都適用。
